# 拾句 · 微信读书桌面组件

一款 Android 应用，把你在微信读书里的划线显示在手机桌面，并支持浏览书架与全部个人笔记。组件会展示原文、书名，以及能关联到该划线的个人想法；点「下一条」切换，约每 30 分钟自动轮播。应用每 6 小时尝试同步，也可以手动同步。

界面采用清爽蓝白风格：浅蓝白背景、深蓝灰文字、白色圆角卡片和蓝色主按钮。阅读页使用大字号引文与浅蓝想法区；书架以蓝色下划线区分栏目、白色分段按钮选择时间范围；底部导航以浅蓝底色标记当前页面。书架采用三列圆角封面网格，真实封面异步加载并缓存；没有封面或离线且尚未缓存封面时显示书名占位。旧缓存会自动补充书架封面信息，无需重新同步全部笔记。底部「阅读」「书架」「收藏」「我的」可直接切换对应页面。

## 构建与使用

1. 在 Codex 中打开此目录，让它检查并配置 JDK 17、Android SDK 35，然后构建 APK。Android Studio 可选；命令行构建命令是 `gradlew.bat assembleDebug`。
2. 安装 `app/build/outputs/apk/debug/app-debug.apk` 到 Android 8.0 或更高版本的手机。
3. 点击底部导航「我的」，在「微信读书」页面输入自己的 `wrk-...` WeRead API Key，点击「保存并同步」。页面提供三步获取说明及[微信读书官方获取页面](https://weread.qq.com/r/weread-skills)入口。切换「AI」可保存、替换或清除 AI API Key，目前仅保存配置，AI 功能后续接入。电脑上的环境变量不会自动传到手机。
4. 长按手机桌面空白处，在组件列表中添加「拾句 · 微信读书划线」。
5. 点击底部导航「书架」，页面只保留「最近阅读」「有笔记的书」「我的收藏」三个栏目。默认进入「最近阅读」，可选择最近一周、最近一月或最近半年，按最近阅读时间从新到旧显示；时间范围从当前时刻分别向前回溯 7 天、1 个月、6 个月，仅显示有阅读或收听记录的书。按书名或作者搜索，选择书籍查看按章节排列的划线、划线想法、章节想法和书评。切换「有笔记的书」可查看已经移出书架的书籍笔记。
6. 点击书封右下角的星标收藏或取消收藏，在「我的收藏」中集中查看和搜索。收藏保存在本机，重新打开或同步后仍保留；即使书籍后来移出书架，也会保留收藏入口。切换账号或清除本地数据时会清除收藏。
7. 笔记右上角的星标支持收藏划线、划线想法、章节想法和书评。书内切换「收藏笔记」查看当前书的收藏；底部导航「收藏」直接展示全部收藏笔记，可按笔记内容、书名或作者搜索。书架内「我的收藏」仍只展示收藏的书籍。笔记收藏保存在本机，重启和同步后保留；笔记移出同步结果时保留收藏时的内容，切换账号或清除本地数据时清除。

升级后请重新同步一次，以获取完整书架、最近阅读时间和个人笔记；旧版划线缓存仍可使用，没有阅读时间的旧缓存会提示同步。同步成功后的最近阅读与笔记可以离线查看，长按笔记文字可复制。最近阅读包含电子书和有声书，文章收藏目录不计入阅读记录；当前接口不提供有声书笔记和收藏文章内容，书签只显示数量。

阅读页使用层叠引文卡片，展示划线、关联想法和书名；下一句实际显示在下层，拖动最上层时，下层卡片随滑动进度逐渐放大、上移并浮到前面。左滑直接甩出当前卡片并查看下一句；右滑先收藏当前句子，再向右甩出卡片并查看下一句，下层直接接替成为当前卡片。只有滑动距离不足、取消操作或收藏失败时才会回弹。卡片拖动时保留倾斜、轻微缩放和阴影变化，上下滚动仍用于查看长内容。已经收藏的句子再次右滑不会重复收藏或取消收藏，仍会切换下一句。卡片不显示标题或底部提示语，也不保留占位，静止时最上层卡片顶部位置不变，高度随内容自然收紧。书架、收藏笔记和微信读书连接通过底部导航进入。

微信读书与 AI 密钥分别由 Android Keystore 加密并保存在设备上，不会写入源码或 APK。书架、划线和想法缓存在应用私有目录；「我的」中「微信读书」页面的「清除密钥和本地数据」会删除微信读书密钥与全部阅读缓存，AI 密钥由「AI」页面的「清除 AI API Key」独立清除。组件本身会在桌面显示私人笔记，请按需使用。

阅读卡片下方显示本地自然周（周一到周日）的阅读日历：本周阅读/收听时长、读过的书籍数和有效阅读天数。日期用紧凑方格展示，蓝色由浅到深表示当天阅读量（0、1至15、16至30、31至60、超过60分钟），日期下方不标时长，也不显示热力图例；今天用蓝色星期文字和小圆点标记，未来日期仅显示灰色日期。点击日期查看具体时长，选中边框保留当天的热力颜色；未同步的日期在详情中显示“—”，已同步但没有阅读显示“0分钟”。首次升级后在“我的 → 微信读书”保存并同步一次，统计会随正常同步更新并可离线查看。统计只累计本周周一至今天，单日满一分钟计为阅读一天。每日时长来自 `/readdata/detail` 的按日秒数，跨月时合并对应月份并仅保留本周已经过去的日期。书籍名单依据书架的最近阅读/收听时间，当前接口不提供每日分书时长，因此书籍区展示本周书籍而非推算的每日分书明细。统计获取失败时保留旧统计，已成功获取的笔记仍可保存。

## 数据来源与行为

- 用 `/shelf/sync` 获取完整书架，用 `/user/notebooks` 获取所有有笔记的书；按 `count` 和 `lastSort` 读取全部笔记本页。
- 最近阅读使用电子书的 `readUpdateTime` 和有声书的 `albumInfoExtra.lectureReadUpdateTime`，按设备时区计算滚动时间范围，不使用书籍更新时间或最近笔记时间替代阅读记录。
- 对有划线或想法的书用 `/book/bookmarklist` 取个人划线和章节；对有个人想法的书用 `/review/list/mine`，按 `count` 和 `synckey` 读取全部页。
- 笔记页面独立保留每条划线、划线想法、章节想法和书评。笔记数量包括划线、想法/点评和书签；可展示的内容不包含书签。组件继续只展示原文及关联的想法。
- 完整同步成功后，将书架、全部笔记和组件划线一起原子更新；同步失败时保留上一次成功的缓存。首次完整同步时间取决于有笔记的书籍数量和网络状况。
- 组件周期更新至少约 30 分钟一次，实际时间受 Android 系统调度影响。

接口请求初始带 `skill_version: 1.0.5`。App 在启动、进入「我的」和同步前检查公开兼容配置，自动检查间隔为 6 小时，也可在「我的 → 微信读书 → 应用与同步更新」立即检查。只有经过我们核对、且当前 App 适配器支持的版本和分页配置才会自动采用；官方出现新版本本身不会自动批准使用。下载失败时保留已保存或 APK 内置的可用配置，不影响离线查看笔记。

服务端返回 `upgrade_info` 时，App 会重新检查一次兼容配置；取得适用的新版本后重试，否则停止本次同步并显示清楚的更新提示，已有缓存仍保留。需要新 App 代码时，「我的」会显示「查看新版应用」入口。兼容配置不包含账号、密钥或笔记，也不执行下载的 Skill 文档。配置维护和单独发布方法见 [兼容配置更新说明](docs/compatibility-updates.md)。

开发验证可运行 `gradlew.bat testDebugUnitTest lintDebug assembleDebug`，单元测试覆盖书架条目、最近阅读筛选与时间边界、完整分页、独立想法与无文字笔记、取消同步和旧缓存兼容。

## 两台电脑继续开发

项目远程仓库为 `https://github.com/zk1047740032/WeNotes.git`。在家第一次使用 Codex 时，可以直接说：

> 请把这个 GitHub 仓库克隆到本机，作为本地项目打开，检查并配置 Android 构建环境，构建一次 APK。以后这个项目请帮我修改代码、验证结果，并在我要求同步时提交和推送。

以后在任一电脑开工时说「先拉取 `main` 最新代码，再按我的需求修改并构建」；换电脑前说「检查改动，提交并推送到 `main`」。Git 负责同步代码，Codex 负责操作 Git 和构建工具。两台电脑都要有各自的本地仓库；聊天记录不会自动把本地源码复制到另一台电脑。

构建产物、本机 SDK 路径、源码压缩包和签名文件都不提交。项目支持固定签名：初始化并私下备份 `.signing/wenotes.keystore` 与 `signing.properties`，另一台电脑还原同一份文件后才能直接覆盖升级并保留手机数据。

## 手机应用内更新

从 1.2.0 起，打开 App 自动检查新版；也可在「我的 → 微信读书 → 应用与同步更新」手动检查。发现新版后，从启动提醒或「查看新版应用」进入下载与安装流程，查看更新说明、下载进度并调用系统安装器。已完成的安装包可以稍后安装；下载失败可以重试。同一新版的启动提醒每天最多一次。

电脑修改代码后需要发布 APK，手机才会检测到更新。第一次先手动覆盖安装带此功能的版本，以后可在 App 中升级。运行 `scripts/initialize-signing.ps1` 固定旧版签名，再用 `scripts/publish-app.ps1 -UseCurrentVersion` 准备当前 release 包；日后提交功能改动后用 `scripts/publish-app.ps1 -Publish` 一键递增版本、构建验证和发布。详见 [应用更新与发布说明](docs/app-updates.md)。

项目协作约定保存在 [AGENTS.md](AGENTS.md)。以后对 Codex 说「发布」，即执行完整发版流程；说「保存」或「同步」，即检查、提交并推送源码。
