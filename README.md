# 拾句 · 微信读书桌面组件

一款 Android 应用，把你在微信读书里的划线显示在手机桌面，并支持浏览书架与全部个人笔记。组件会展示原文、书名，以及能关联到该划线的个人想法；点「下一条」切换，约每 30 分钟自动轮播。应用每 6 小时尝试同步，也可以手动同步。

界面参考微信读书的浅灰背景、深灰文字、蓝色文字标签与底部导航。书架采用三列封面网格，真实封面异步加载并缓存；没有封面或离线且尚未缓存封面时显示书名占位。旧缓存会自动补充书架封面信息，无需重新同步全部笔记。底部「阅读」「书架」「收藏」「连接」可直接切换对应页面。

## 构建与使用

1. 在 Codex 中打开此目录，让它检查并配置 JDK 17、Android SDK 35，然后构建 APK。Android Studio 可选；命令行构建命令是 `gradlew.bat assembleDebug`。
2. 安装 `app/build/outputs/apk/debug/app-debug.apk` 到 Android 8.0 或更高版本的手机。
3. 首页点击「管理微信读书连接」，进入独立连接页面，输入自己的 `wrk-...` WeRead API Key，点击「保存并同步」。页面提供三步获取说明及[微信读书官方获取页面](https://weread.qq.com/r/weread-skills)入口。电脑上的环境变量不会自动传到手机。
4. 长按手机桌面空白处，在组件列表中添加「拾句 · 微信读书划线」。
5. 首页点击「查看书架与笔记」，按书名或作者搜索，选择书籍查看按章节排列的划线、划线想法、章节想法和书评。切换「有笔记的书」可查看已经移出书架的书籍笔记。
6. 点击书封右下角的星标收藏或取消收藏，在「我的收藏」中集中查看和搜索。收藏保存在本机，重新打开或同步后仍保留；即使书籍后来移出书架，也会保留收藏入口。切换账号或清除本地数据时会清除收藏。
7. 笔记右上角的星标支持收藏划线、划线想法、章节想法和书评。书内切换「收藏笔记」查看当前书的收藏；书架「我的收藏」中点击「查看全部收藏笔记」，可按笔记内容、书名或作者搜索所有收藏笔记。笔记收藏保存在本机，重启和同步后保留；笔记移出同步结果时保留收藏时的内容，切换账号或清除本地数据时清除。

升级后请重新同步一次，以获取完整书架和个人笔记；旧版划线缓存仍可使用。同步成功后的书架与笔记可以离线查看，长按笔记文字可复制。书架包含电子书、有声书和文章收藏入口；当前接口不提供有声书笔记和收藏文章内容，书签只显示数量。

首页的「我的书架」「连接微信读书」「此刻的一句」支持长按模块并上下拖动排序；靠近屏幕边缘会自动滚动，松手后自动保存顺序，下次打开仍会保留。开启屏幕阅读器时，也可通过模块的「上移模块」「下移模块」操作调整顺序。

密钥由 Android Keystore 加密并保存在设备上，不会写入源码或 APK。书架、划线和想法缓存在应用私有目录；连接页面中的「清除密钥和本地数据」会删除密钥与全部缓存。组件本身会在桌面显示私人笔记，请按需使用。

## 数据来源与行为

- 用 `/shelf/sync` 获取完整书架，用 `/user/notebooks` 获取所有有笔记的书；按 `count` 和 `lastSort` 读取全部笔记本页。
- 对有划线或想法的书用 `/book/bookmarklist` 取个人划线和章节；对有个人想法的书用 `/review/list/mine`，按 `count` 和 `synckey` 读取全部页。
- 笔记页面独立保留每条划线、划线想法、章节想法和书评。笔记数量包括划线、想法/点评和书签；可展示的内容不包含书签。组件继续只展示原文及关联的想法。
- 完整同步成功后，将书架、全部笔记和组件划线一起原子更新；同步失败时保留上一次成功的缓存。首次完整同步时间取决于有笔记的书籍数量和网络状况。
- 组件周期更新至少约 30 分钟一次，实际时间受 Android 系统调度影响。

接口请求均带 `skill_version: 1.0.4`。若服务端返回 `upgrade_info`，应用会停止同步并显示更新提示，需要升级接口适配代码。

开发验证可运行 `gradlew.bat testDebugUnitTest lintDebug assembleDebug`，单元测试覆盖书架条目、完整分页、独立想法与无文字笔记、取消同步和旧缓存兼容。

## 两台电脑继续开发

项目远程仓库为 `https://github.com/zk1047740032/WeNotes.git`。在家第一次使用 Codex 时，可以直接说：

> 请把这个 GitHub 仓库克隆到本机，作为本地项目打开，检查并配置 Android 构建环境，构建一次 APK。以后这个项目请帮我修改代码、验证结果，并在我要求同步时提交和推送。

以后在任一电脑开工时说「先拉取 `main` 最新代码，再按我的需求修改并构建」；换电脑前说「检查改动，提交并推送到 `main`」。Git 负责同步代码，Codex 负责操作 Git 和构建工具。两台电脑都要有各自的本地仓库；聊天记录不会自动把本地源码复制到另一台电脑。

构建产物、本机 SDK 路径、源码压缩包和签名文件都不提交。两台电脑默认的 Android 调试签名不同；如果要直接覆盖安装同一部手机上的调试版，需要使用相同签名，否则卸载旧调试版后重装并重新同步。
